## What's new

### Linux SFTP senders deliver to a Windows collector (SFTP1)

- A Linux sender whose inbox is an SFTP (sshfs) mount, such as one set up with `ACCOUNT@COLLECTOR:/PATH` in 0.26.0, could not deliver to a Windows collector: "copy batch N … permission denied", leaving a 0 KB file in the inbox. sshfs looks up each file right after creating it, and the drop-only inbox allowed senders nothing on a file once it existed.
- Collector setup (and the upgrade) now also lets **Blackbox Senders** read the attributes and permissions of files in the inbox, not their contents. Senders still can't list the folder, read, change, rename or delete anything in it. Upgrade the collector; batches waiting on senders are delivered at their next run.
- 0 KB files left by the failed attempts are set aside in `inbox\rejected` after 10 minutes, as any file that is not a complete delivery.
