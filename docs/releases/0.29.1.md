## What's fixed

- **Defender flagged Blackbox (`Behavior:Win32/Execution.A!ml`) after the 0.29.0 upgrade.** To clean up old status-icon tasks, 0.29.0's setup ran `schtasks.exe` hidden up to 20 times in a burst, which Defender's behaviour rules took for an attack. Setup now lists the tasks with one call and removes only the ones that exist.
- **No status icon after upgrading.** This was most likely Defender stopping `blackboxw.exe` (see above). If Defender quarantined the files, restore them from Protection history, or reinstall with 0.29.1.
- **`blackbox tray` from a terminal** now starts the status icon in the background and returns, so closing the terminal or pressing Ctrl+C no longer takes it away.
- **Setup: no Network page.** Only "This computer only" asks about the network, as one box on the first page, **Not on a network (standalone)**, ticked by default. Collectors and senders are not asked. The console asks "On a network? (y/N)".
- **Setup: the VirtualBox option** is unticked by default, and its explanation and account box appear only once it is ticked.
- **Setup: shorter role descriptions** on the first page.

## Not verified live

- The setup window was built and type-checked for Windows but not run.
- We haven't confirmed that 0.29.1 no longer triggers Defender's behaviour detection, because we can't reproduce Defender's cloud machine-learning here. Signing the program (A10) is the lasting fix. A false-positive report to Microsoft (WDSI) helps too.
