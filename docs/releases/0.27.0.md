## What's new

Security fixes for collectors. Senders need no change, but upgrading them too is fine. These fixes come from a code review and are not a complete security audit.

### Unsigned or damaged deliveries can't change a sender's records (SEC4)

- Before: a batch that could not be read, or whose signature did not verify, was set aside but still recorded the batch number written in it. Anyone able to write to the inbox could fake missing batches, or move a sender's last batch number forward.
- Now only a delivery whose signature verifies updates a sender's records (last batch, missing batches, pinned key). Others are still set aside and reported.

### A SCAP result file may only report on the computer that sent it (SEC5)

- Before: only the first result in a file was checked against the signature. A sender could add results for another computer, and they showed in the report as that computer's scan.
- Now every result in the file must be for the signing computer, or the file is set aside. Reports also ignore a stored result that is filed under another computer's folder.

### Set-aside files are kept out of the inbox (SEC6)

- Before: files set aside or held were kept in `inbox\rejected`, a folder senders could create first. Links placed there could make the collector (root or SYSTEM) write its notes over other files.
- Now they are kept in `inbox-set-aside` in the data folder, and held files in `inbox-set-aside\held`. What earlier versions set aside moves there at the collector's first import after the upgrade.
- The collector opens an inbox file only if it is a regular file. A link, pipe or device is set aside without being opened.
- `blackbox status` and the report give the new folder.

## Upgrade

- Upgrade the collector as usual (setup or `blackbox install`). Nothing else to do.
- Going back to 0.26 afterwards is not recommended. 0.26 looks for set-aside files in `inbox\rejected`, so it would not list the ones already moved.

## Not verified live

- Tested by automated tests on Linux and Windows CI only, not on a live collector.
- The link and pipe tests run as root, not as a real unprivileged sender account.
