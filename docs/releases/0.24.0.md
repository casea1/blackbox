## What's new

Fixes from the 0.23.0 live check (8 Oct 2026), and the report redesign the owner chose page by page the same day. Blackbox still only reports; it changes no system or audit settings.

### Upgrade the senders first, then the collector

- **Why:** a 0.24 collector makes its inbox drop-only (below). Senders older than 0.24 write a temporary file and then rename it, and a Windows collector's drop-only inbox does not allow renaming. So if a Windows collector is upgraded first, its 0.23 senders can't deliver until they are upgraded too.
- **Senders first avoids any wait.** A 0.24 sender names its files `HOST_SENDERID_SEQ-RANDOM.bbx`, which a 0.23 collector reads too. While the collector is still 0.23, a sender that has its own 0.23 folder there keeps delivering into it. Once the collector is upgraded and the folder is gone, it delivers into the inbox.
- **Nothing is lost either way.** A sender that can't deliver keeps its batches and sends them once it is upgraded. Linux collectors are not affected (an old sender can still rename its own file there).
- A 0.23 collector reads a file in the inbox itself as soon as it sees it, so it may catch a 0.24 batch half written and set it aside as incomplete. `blackbox gaps` lists it, and `blackbox send --resend` on the sender sends it again.

### A drop-only inbox replaces 0.23's per-sender folders (DESIGN1, SEC1b, SEC1c)

The per-sender folders of 0.23 needed an account and an `inbox add` per computer, weren't in setup, didn't help when senders share one delivery account, could be taken before they were made (SEC1b), and lost or double-imported batches when a sender was moved (SEC1c). They are gone. There is one inbox again, and nothing to set up per computer.

- **Senders can add files to the inbox, but can't list, read, change, rename or delete anything in it,** their own files included. Setup and the upgrade apply this on the collector:
  - **Windows:** Blackbox Senders has *Create files / write data* and *Synchronize* on the inbox folder only. OWNER RIGHTS has no rights, so a sender gets nothing from owning a file it made. Administrators and SYSTEM keep full control.
  - **Linux:** the inbox is owned by root and the group `blackbox-senders` (setup makes it), mode `1730`. A sender can create files there, but can't list the folder or remove anyone else's files.
  - **The marker file `BLACKBOX-INBOX.txt` stays readable to senders** (owner's decision), so a sender can still tell the collector's inbox from a share that isn't connected. Everything else in the inbox is unreadable to them.
- **Senders write each file once, under its final name** `HOST_SENDERID_SEQ-RANDOM.bbx`, and only if no file has that name. A name already taken is retried under a new random part. A batch counts as delivered when it was written and closed; the collector's missing-batch list (`blackbox gaps`, then `send --resend`) is the check.
- **A file the collector can't read whole** may still be being written. It is left for 10 minutes after it was last written, then set aside in `inbox\rejected` as incomplete.
- **The 0.23 folders are emptied at the collector's upgrade** (and at its next run): what waits in them is imported like any other delivery, and the folders are removed. Each sender's import record (last number, missing batches, the hashes behind "already imported") is kept by sender ID, so nothing is missed or imported twice. In the SEC1c case, batches 431–433 are imported once, never listed as missing, and not imported again.
- **`blackbox inbox` and `blackbox inbox add` are removed.** Running them says what replaced them.

### Signed deliveries and key pinning (DESIGN1, SEC1b, SEC1c, SEC1d)

- **Each sender signs everything it delivers** (batches, original-log archives and SCAP results) with its own **Ed25519** key, which is inside Go's FIPS 140-3 module.
  - The key is `sender-key.pem` in the data folder: Administrators and SYSTEM only on Windows (the access list is set whole, not by icacls), root `0600` on Linux. It never leaves the computer.
  - `blackbox status` on the sender and setup's last screen show `Signing key: SHA256:…`, to compare with what the collector shows. `status` says so if the key file can be read by any other account.
  - The signature covers the file's SHA-256, the computer's name, its sender ID, what the file is (a batch's number, an archive's period, a SCAP result's hash) and when it was signed. A batch carries it in its end marker; an archive or SCAP result in `NAME.sig` beside it. A leftover `NAME.sig` with no file is removed after 10 minutes.
  - A signature that doesn't verify is refused into `inbox\rejected` with the reason.
- **Trust on first use.** A computer's first signed delivery pins it to its key. The collector says so once: a "New sender: … (key SHA256:…, first seen …)" line in `status`, an Info row in the next report and a **New senders** line under Needs attention.
  - New setting `new_senders = accept|hold` (default `accept`; in setup, "Accept new computers automatically", ticked). With `hold`, a new computer's deliveries wait until `blackbox senders approve NAME`.
- **A key change** (a reinstall, a re-imaged computer, a restored data folder) is not imported. Its files wait in `inbox\rejected\held`, with a High row and a `status` line naming the fix: `blackbox senders rekey NAME`. After that, the held files are imported.
- **One key on two computers** (a computer copied with its data folder) is a High row; neither is merged into the other. `blackbox send --new-id` makes a new key as well as a new sender ID.
- **New commands on the collector:**
  - `blackbox senders` lists each computer with its key fingerprint, first seen, last delivery, and whether it signs;
  - `blackbox senders approve|rekey|forget NAME ["why"]`, each written to Application event 102 or the journal with who did it and why.
- **In the report:** each system's page has "Delivery: signed · key SHA256:… since 8 Oct"; Needs attention lists new, held, unsigned and shared-key senders; the Verified pop-up adds "All deliveries were signed by their computer's key".
- **The 0.23 checks stay as a second line** (sender ID, numbering, former names, content hashes). The account that wrote each file is still recorded, as information only: signatures decide what is accepted.

### Unsigned senders during the upgrade (DESIGN1)

- For this release, the collector still accepts unsigned deliveries from a computer that has **never** delivered signed (a sender not yet upgraded). `status` lists them, "upgrade these to 0.24", and they are marked "unsigned" in `blackbox senders` and on the system's page.
- Once a computer has delivered signed, an unsigned delivery claiming to be from it is refused.
- New setting `require_signed = no|yes`: default `no` in this release, `yes` from the next.
- A sender upgraded with batches still waiting signs them as it delivers them, with no gap, no rejection and no double import.

### Smaller (CLI2, LEDGER4b, TZ1b, SEC1d)

- **Options anywhere (CLI2).** `gaps accept`, `reports accept`, `systems rename`, `verify` and the new `senders` commands read options anywhere after the subcommand. `--` ends them, for a reason that starts with a dash.
- **Only copy of the original logs (LEDGER4b).** "It held the only copy of that period's original logs" is said only when a `logs-*.zip`, or the whole report, is missing or changed: in event 101, `status`, the tray, the report and the index.
- **UTC throughout (TZ1b).** `piece.json` and `archive.json` write every time in UTC (`Z`), gaps and log coverage included.
- **Retired computers (SEC1d).** A computer removed with `blackbox systems remove` is left out of every sender warning in `status` and the report, and its missing batches no longer make `status` exit 4. `blackbox gaps` still lists them.
- **Setup's last screen on a collector (SEC1d)** says "Other computers send to C:\BlackboxInbox. Each one signs what it sends; new ones appear in blackbox status." The per-folder wording is gone.
- **Reinstalling a sender as a collector** with `--inbox` now makes a collector. Before, the kept `send_to` won and it quietly stayed a sender.
- **`status` lists an original-log gap once,** even when the packed archive names it twice.

### Report redesign (UI-R1)

The report has a new layout, page by page, chosen by the owner on 8 Oct 2026 (issue #103). It is still one offline folder you open in a browser, with the same look, and everything it worked out before is still in it somewhere. It was built and checked on a made-up 30-system network (11 servers, 19 workstations, local accounts only) and on the usual 3-system data.

**Every page**

- **Sidebar.** Five groups, always open: Review (Overview, Detections, Search), Who and what (Systems, People), Evidence (Audit health, Original logs), Events by kind and More (Inventory, Trends).
- **Events by kind** has five pages, each with its count: Privileged activity, Audit integrity, Logon activity, Other security and PowerShell (owner's decision). Where the old pages went:
  - Failed logons → Logon activity ("Failed: bad password", "Failed: expired", "Failed: locked out");
  - USB & removable → Other security ("USB connected or removed", "USB files copied", "USB blocked");
  - Accounts & groups → Privileged activity ("Account created", "Account changed", "Account added to group", "Account disabled").

  Old links still work: `#failed` opens `#logons?part=failed`, `#usb` opens `#other?part=usb` and `#accounts` opens `#privileged?part=accounts`. Search's Kind list and each system's Events by kind use the same five.
- **Report card** at the bottom of the sidebar: the report type, period, systems and when it was made, "✓ Verified · files match manifest" (opens the Verified pop-up) and "All reports →". The period, Verified and All reports are no longer in each page's header.
- **One header** on every page: a breadcrumb with the period and time zone, the title, and only that page's buttons (usually Export CSV).
- **Times** are local, with the zone said once per page. The event panel shows local time and UTC.
- **Systems are grouped** Servers / Workstations wherever they are listed. Problems come first; quiet things are folded ("18 more systems with no problems").
- **One rule for a "problem" everywhere** (owner's decision): a red check, a high detection, or a red Delivery line (held, waiting for a rekey, or one key on two computers) makes a system a problem; an amber check, a medium detection or an unsigned sender a warning. Overview and Systems now count the same.
- **Export** is one menu: "This page" (what the page shows, as CSV) and "Whole report" (Summary, All events, Systems and drives, Audit settings to fix, Open SCAP findings, the report folder). Every CSV time carries its offset from UTC.
- **Verified** is shorter: "This report has not been changed", three checks, and "Check it yourself: `blackbox verify`". A failed check turns the title red and comes first, with its file.

**Overview**

- One line says what needs review ("Needs review: 7 high detections, 2 systems not reporting"), or "Nothing needs review" in green.
- One row of numbers: Detections, Systems reporting, Events, Audit settings.
- Up to 8 detections, one line each (title, short reason, system, time); a line opens it on Detections.
- **Needs attention:** one line per kind of problem, with the systems (named when one or two). Then one "Fine: …" line.
- **Original logs never put in a report (RET1)** is now a red line here, naming the systems. It links to Original logs.
- Activity per hour, Windows and Linux stacked, a red dot on hours with a detection; a bar opens Search for that hour.
- **Systems at a glance:** only the systems with a problem, with six check squares, then a link to all of them.
- Gone: the four large tiles, the health bar, the "1 of 3 systems" column, "No new admins…". **What changed moved to Trends** ("Biggest changes this week").

**Detections**

- A filter bar (High / Medium, System, Person, Servers / workstations), the list grouped High and Medium, and the chosen detection on the right.
- The detection: one plain sentence, four facts (System, Person, When, Record), and why it matters.
- **What happened** is one timeline: the events 10 minutes either side, its own events marked. It replaces the separate "What happened" and "Events" panels. Buttons: Open in Search (±10 min), Everything <person> did.
- **Related this period:** other detections with the same person or system.

**Search and Events by kind**

- One box that searches every field, with Kind, Person, System, Servers / workstations, Severity and When. The eight common-search tiles are one "Common searches ▾" menu.
- Field counts on the left (click to filter, Alt-click to leave out), events per hour, and the results with "Group by ▾" and "Show 50 more".
- Each **Events by kind** page is Search with its Kind set. Clear the Kind chip for every event. Their own charts and Top people / Top systems panels are gone.

**Event panel**

- Opens from any event row. The event in plain words, its severity, and the detection it belongs to. Going to another page closes it.
- When (local and UTC, to the millisecond), System, Person, Program, Command, Started by, Outcome, and the **original record** (`logs-<host>.zip › <file>.evtx`, record n).
- **Around it:** four events either side on that system.
- **Seen before** (new): whether earlier scheduled reports saw this person on this system, or this USB device, service or address ("never on SRV-DC02 in 30 reports").
- The ATT&CK technique where the mapping is clear, and how many other systems ran the same command.
- Buttons: Everything <person> did, ±10 min, **Copy for a ticket**, Raw record.

**Systems**

- One table grouped Servers / Workstations, worst first, with Find, All / Problems / Warnings / OK, OS and Role.
- Six check squares per system: Reporting, Logs intact, Settings, Antivirus, Orig. logs, SCAP.
- **One system** (`#systems/NAME`): its problem, what it is, six facts, its Delivery line, and a **collection strip** (one cell per expected collection: missed, overwritten, log cleared). Then its checks, detections, activity, who was active and events by kind.

**People**

- The list is grouped Administrators / Users / Shared and service accounts, with All / Detections / Admins and "Find a person or account".
- A person: where their local accounts are, six facts, **Where and when** (one lane per system), notable actions, and **Accounts named <name>** (one row per system's account).
- Shared and built-in accounts (root, Administrator, service accounts) say "not one person" and split **Who acted as** them: by person (sudo, su, RunAs), jobs and services, and direct logons. A box says plainly whether anyone logged on as the account directly.
- **New setting `people_aliases`** merges spellings of one person across systems: `blackbox config set people_aliases "jlee=j.lee,jlee2"`. The merge is shown in the "Accounts named" table. Same-name accounts are always one row.

**Audit health**

- Four cards: Audit settings match the STIG, SCAP, Antivirus, Logs.
- Tabs: Settings to fix · By system · SCAP · Antivirus · Log sizes (`#health/@av` and so on open one).
- **Settings to fix:** one row per setting, the setting on most systems first. Each row has its STIG IDs (or "Blackbox's advice"), what the report misses without it and how many systems. Open it for the systems and the fix ("One GPO on the OU fixes all 9").
- **Settings problems are on Audit health only.** Missing systems, cleared logs and original logs never reported are no longer Audit health gaps. They are on the Overview, Systems, Detections and Original logs.

**Original logs**

- Four cards: logs in this report, Complete, With a gap, Checked (every zip against its SHA-256).
- One table grouped Servers / Workstations, gaps and missing first, with a status chip and a short note. "All / Gaps and missing" switches between them.
- **Giving these to an assessor:** three steps (`sha256sum -c manifest.sha256` or `blackbox verify`; Event Viewer or `ausearch -if`; each zip's `archive.json`). The same text is in each report folder's `README.txt`.

**Inventory**

- Systems on the left, grouped, with "Find a system or serial": a drive's serial number finds its system.
- Each system's **drives with serial numbers**, type and a note ("internal", or "seen 7 Oct 10:18 · not connected now" for a USB drive seen in the events), and five accounts with "Show all".
- Export CSV: one row per drive and one per account.

**Trends**

- 4 / 8 / 12 weeks, Export CSV, and **Monthly summary (PDF)** (the page printed).
- Six small charts by calendar week, each with this week and "usual N". This week's bar is red when worse, green when better.
- **Biggest changes this week** (formerly the Overview's What changed), detections by system by week, and **New this week**: a new admin, account, logon path, source address, service or USB device.
- Each scheduled report's `summary.json` now keeps the sets these are compared with (`seen`). Reports from before this release have none: Seen before starts once a report from this release exists, and New this week the week after.

**All reports**

- Four cards: latest report, next report, reports checked (from the ledger) and what the folder holds.
- One table grouped by month, with Latest / Manual chips, notes, systems, events, High, Medium, original-log size and the ledger's check. Filters: All / Scheduled / Manual / With high / Problems, then "Show older".
- **Notes show only what Blackbox works out itself** (latest, changed, missing). A manual report carries no reason (owner's decision); the unused `reason` field is gone from `summary.json`, and older files that have it are still read.
