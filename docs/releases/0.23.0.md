## What's new

Fixes from the 0.21.0 full test (8 Oct 2026): a source review, a compliance review and live checks on all three test systems. Blackbox still only reports; it changes no system or audit settings.

### The collector's inbox is a trust boundary (SEC1, SEC2, SEC3)

- **Each sender has its own folder** in the inbox, which only its account can write to. Make one per sending computer on the collector:
  - command: `blackbox inbox add NAME ACCOUNT [--host COMPUTER]`;
  - Windows: the account can create and write files there, not delete or rename them;
  - Linux SFTP: one directory per account.

  Senders find their folder by themselves from 0.23 on. The shared inbox folder still works for this release; `blackbox status` lists the senders still using it.
- **What a folder holds must be from that folder's computer.** A batch, original-log archive or SCAP result claiming to be from another computer is set aside. The collector records which account wrote each file.
- **Nothing is thrown away unread.** These are kept and raised as a High row in the next report:
  - two different batches under one number;
  - two computers using one sender ID (a cloned computer: run `blackbox send --new-id` on one);
  - two different original-log archives for one period;
  - a former name that belongs to another computer still reporting.

  A batch is "already imported" only when it is the same batch.
- **Former names** are taken only when the same sender used them before, or after `blackbox systems rename OLD NEW`.
- **A sender's first batch for this collector** is taken only near the next number expected. A recorded gap is never erased by it.
- **Bad batches are set aside, not stuck.** A batch whose records can't be read goes to `inbox\rejected` with a `.why.txt`. Importing carries on, and the batch's number stays missing until it is sent again. `status` lists rejected files and exits 4, and the report says so.
- **Other inbox checks:**
  - archives named `.` or `..` are refused;
  - oversized batches are refused before they are read;
  - SCAP results must match the hash in their name.

### Ubuntu 26.04 SSH logons (LNX1)

- Ubuntu 26.04 writes no `USER_LOGIN` record, so with auditd its SSH sign-ins were missing from every report. Its session start (`USER_START`, sshd) is now the logon.
- auth.log's sshd lines are read alongside the audit log, for the method and key fingerprint and for failed tries. Each sign-in or failed try is still one row.
- `blackbox check` warns when the audit log has SSH sessions but no logons.
- Ubuntu 26.04 is listed as supported.

### Separate actions stay separate rows (DUP3, DUP4)

- Each log clear is its own row and count, even a minute apart. The detection reads "3 logs cleared on WIN11-TEST between 16:24 and 18:59".
- Two SSH logons are joined only when their addresses match.
- Only the real `C:\Windows\System32\conhost.exe`, with its usual arguments, is folded away.
- An `auditpol /set`, `/clear` or `/remove` is folded into the audit-policy change it made, under "Changed with". One change is one High row.

### Retention never deletes logs that never reached a report (RET1)

- Report folders are aged by the end of their period, not the folder's date. A folder restored from backup is safe.
- Original logs waiting for a report are never deleted. When they are older than `retention_days`, `status` (exit 4) and the report say so: "original logs from … have waited N days and were never put in a report".
- `config set retention_days` explains that the period comes from your records schedule (NARA GRS / DoD records schedule, the ISSM), not from AU-11. It also says not to shorten it under a legal hold.

### Compliance claims (COMP1, COMP2, COMP3, AU3, DOC1)

- **Windows 11 baseline (COMP1).** It is now the Windows 11 STIG V2R11. File System success/failure and Handle Manipulation success (WN11-AU-000581/582/584) are no longer STIG rules since V2R8; they are shown as Blackbox's advice. This was checked against the stigaview.com mirror on 8 Oct 2026, not DISA's own site.
- **Linux STIG IDs (COMP2).** Linux checks cite the STIG IDs of Ubuntu 24.04 and 22.04, AlmaLinux 9 and RHEL 9 and 8. A check with no STIG ID reads "Blackbox recommends …", is counted on its own as Blackbox's advice, and is left out of "Systems matching STIG".
- **FIPS 140-3 (COMP3).** Releases are built with Go's FIPS 140-3 module (`GOFIPS140=v1.0.0`, CMVP #5247) and run in FIPS mode. `blackbox version` says so on a second line.
- **Outcome (AU3).** Every event has an outcome where its source records one; `events.csv` says "not recorded" where it doesn't.
- **Documentation (DOC1).** It no longer claims more than Blackbox does. It now says:
  - Blackbox collects often, and detects and reports any loss;
  - it never alters or clears log records, and writes its own change records;
  - the manifest supports AU-9b detection;
  - AU-5 holds within the report and `status` interval.

### Original logs and integrity (LC2c, VER2, DST1)

- **Cleared logs (LC2c).** A cleared log always leaves a "cleared" gap in the original logs and in `status`, however full the log was.
- **verify (VER2).** `blackbox verify` checks every file in the report folder: a file not in the manifest fails it, and so does a listed file it can't read. The report ledger also notices files added to a report.
- **Time offsets (DST1).** Each row keeps its own UTC offset, so times and days are right on daylight-saving days.

### Smaller (ROLE1b, UX10b, STAT2, TZ1, UI19, UI20, UI21, LEDGER4, SEC3c, SEC3d)

- **Retired computers (ROLE1b).** A computer retired with `blackbox systems remove` shows as "retired 7 Oct by …" in its own group on Systems. It no longer counts as a computer that isn't reporting or has problems.
- **Setup (UX10b).** Setup records a settings check, with the inventory, at every install and upgrade. Ubuntu Server is grouped with the servers at once.
- **status (STAT2, TZ1).**
  - `status` gives the PowerShell log's size advice once, as a stable 1 or 2 GB.
  - It shows local times only, naming the time zone once at the top.
  - `archive.json` times are all in UTC.
- **Accessibility and layout (UI19, UI20).**
  - Screen readers can now name the filter menus and charts. The landmarks and heading order are fixed.
  - Audit health has a column key and no sideways scrolling at 768 px.
  - At phone width the Overview tiles wrap instead of cutting off.
- **Wording (UI21).**
  - A change found in a saved original log says Blackbox's own check found it when the report was made.
  - A 4648 without a process name no longer ends "to run .".
  - `powershell -File` reads "ran the script …".
- **Report ledger (LEDGER4).** A scheduled report that goes missing or changes is also written to the system log (Windows Application event 101, or syslog `blackbox`), once.
- **Settings file (SEC3c, SEC3d).**
  - Upgrades keep the first `blackbox.conf.old` and name later copies `.old.<version>`.
  - The share password's Windows protection (DPAPI, machine scope) is documented.

Release files are still unsigned: the signing secrets (A10) have not been set yet.
