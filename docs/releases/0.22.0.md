## What's new

Fixes from the assessor test of 8 Oct 2026, where a real scheduled report was checked as evidence and every row was traced back to its original record. The original logs no longer depend on the clock, and a report folder now explains itself to someone who receives only the folder. Blackbox still only reports; it changes no system or audit settings.

### The original logs are exported by position, not by time (AR8, AR9)

- Exports used to pick records by time, which lost two kinds of record:
  - a Linux audit record written in the same second as a run, after the cut (33 serials were missing from the 6 Oct report, 16 of them rows of the report itself);
  - anything stamped while the clock was set back, including the record of the clock change itself and a logon made meanwhile.
- Each export now starts exactly where the last one ended, whatever the records' times:
  - **Windows:** after the last record ID exported;
  - **Linux:** after the last byte of each log file, finishing a file rotated since;
  - **systemd journal:** after its cursor.
- The times in `piece.json` and `archive.json` are for reading only.
- **Gaps:**
  - Records a log no longer holds when it is exported (it overwrote them) are a gap named by number, e.g. "records 172279-172285".
  - On Linux, audit serials that don't follow on are a gap: "audit serials 41323-41330 are not in the audit log".
  - `status`, Original logs and Audit health say which records.
- The first export after upgrading is by time once more, now to the millisecond. It sets each log's position.

### Original logs coverage (AR10)

A sender archives once a day on its own schedule, so its zip need not line up with the report's period. The Original logs page now says where a computer's zip starts and, when it ends before the period does, that the rest is in the next scheduled report's folder.

### A report folder an assessor can use on its own (ASSESS1)

- **`README.txt`** in every report folder. It says:
  - what each file is;
  - how to check them without Blackbox (`sha256sum -c manifest.sha256`, or `Get-FileHash` in PowerShell);
  - how to open the original logs (`Get-WinEvent -Path …`, `ausearch -if audit.log`);
  - the time zone.
- **`events.csv`** times carry their offset (`2026-10-06 23:00:00 -07:00`). A new `time_utc` column gives them in UTC, like the archive names.
- **Message text (Windows):** each exported `.evtx` carries its message text (`LocaleMetaData`, from `wevtutil al`), so its events read the same on a computer without the programs that wrote them.

Release files are still unsigned: the signing secrets (A10) have not been set yet.
