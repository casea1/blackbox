## What's new

Fixes from the 0.11.0 re-test: a fresh Windows 11 Pro 25H2 standalone PC tested live, plus the recorded Ubuntu and Server 2025 logs.

### Clock changes

- **T3 (High)** Setting the clock back can no longer keep events out of reports. Each report now covers what was collected since the previous one, in collection order, whatever the clock said. A period never starts after it ends. Events recorded while the clock was ahead go into the next report rather than waiting for the clock to catch up. When the clock was moved back, the report has a High detection, "The clock was moved back", and `blackbox status` says so and exits with code 4. Windows event 4616 that moves the clock back by 5 minutes or more is now High.
- **T1** The Windows collection task's repeating trigger now starts at a fixed time in 2000, so a clock corrected after install no longer pauses collection. A run that finds the last collection in the future registers the task again. `status` no longer says "just now" for a collection time in the future.
- **C6** Windows 11's Security log fails `check` below WN11-AU-000505's 5,120,000 KB (STIG V2R8). Collection now runs every 15 minutes by default, not every hour. `blackbox status` exits with code 4 when events were lost to log rollover.

### Noise on a fresh Windows 11

- **A13b, A13c, A13d** Firewall rules changed by the Windows Firewall service are counted by its account name or SID. A rule with no name shows its rule ID. Rules Windows changes for WinDefend as SYSTEM are counted, not listed.
- **A16** Defender's settings bookkeeping (5007) is one Info row per day. Exclusions, real-time protection, `Disable…` switches, tamper protection and policy keys keep their own rows. `DisableBmNetworkSensor` turned on is Low with a note.
- **A17** The out-of-box setup's `defaultuser0` and `MINWINPC` events are one Info "Windows setup" row. Covering-of-tracks no longer pairs with Defender's own changes or SYSTEM.
- **T4** A deleted report is one High row, not one per file. Blackbox's own writes to its data folder and the programs it starts are left out. 4717/4718 (logon rights) read as a sentence when a person made the change.
- **T2** A 5038 on a Defender platform file stays High. Not confirmed as a documented false positive, so the row says Windows often logs this during a Defender platform update, and how to check.

### Delivery

- **L11** A sender now keeps each batch for `keep_sent_days` (default 14) after delivering it. If the collector reports batches missing, `blackbox send --resend 214-219` on the sender sends them again. The collector imports those that fill the gap and ignores the rest. The report's gap warning and `blackbox status` name the command to run. Each resend is recorded in the report and the system log, like a setting change. Kept copies stay in the data folder (root/SYSTEM only), which the recommended audit rule and auditing entry already cover.
- **N2** Setup still never opens the firewall. When Windows Firewall blocks file sharing on a collector, setup and `blackbox status` now print the exact command for one inbound rule (TCP 445, the senders' addresses only, Domain and Private profiles) and the Group Policy path. When the collector runs the OpenSSH server for SFTP senders and TCP 22 is closed, the message names port 22 and the OpenSSH server.
