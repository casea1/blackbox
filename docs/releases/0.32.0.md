Worker prompt 15 (#141), from the 0.30.0 live test.

## What's fixed

### SEND2: a Windows sender stuck on an old network connection

Windows lets each logon session hold one connection per server, under one account. When a sender's `share_user` changed, the scheduled runs (as SYSTEM) kept their old connection to the collector, even after that account was deleted. Once the collector restarted, every send failed with "The user name or password is incorrect" while the setting and password were right.

- When the server already has a connection under another account, Blackbox now closes it (the share and `IPC$`) and connects again as `share_user`. It doesn't force it closed while files are open on it.
- If it still can't, the message says it is already connected to the server as another account, and how to clear it (`net use \\SERVER\SHARE /delete`, as SYSTEM). It no longer gives the logon error.
- Setup's first send on a Windows sender now says that it ran as you, and that the scheduled sends (as SYSTEM) are checked at their next run (`blackbox status`).

### DET5: one detection for one continuing run of failed logons

A sender with an old password failed to log on every few minutes for days: 92 High "Possible password guessing" detections a day for one cause.

- Bursts of failed logons for one account, from the same source and less than an hour apart, are now one detection. It gives the total, the first and last time, "One continuing run", and "Still going at the end of this period" when it is.
- When the account doesn't exist on the computer (0xC0000064), the detection says so.
- When the account is or was in **Blackbox Senders**, or the logons come from a computer that reports here, it adds "Probably a sender with an old or wrong password". It names the systems that were silent or late in the period.
- A separate burst against another account stays its own detection.

### Smaller fixes

- **DET6:** setup's own write-test file in the reports folder (`.blackbox-write-test-*`) is no longer a High "Blackbox's files changed".
- **DET1c:** a delete that failed with "No such file or directory" is "(failed)", not "(refused)". "Refused" now means the system denied it (EACCES, EPERM).
- **UI23:** the Systems page's Status column no longer repeats the system's own name ("… on WIN11-TEST").
- **UPG1b:** setup writes `network = lan` instead of leaving it blank. Blank already meant lan.
- The 0.29.0 release notes named `99-blackbox.rules`; the file is `zz-blackbox.rules`.
