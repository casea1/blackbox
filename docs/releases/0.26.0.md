## What's new

Two setup improvements. Blackbox still only reports; it changes no audit settings.

### Reports in a folder open only to a group (Windows)

- A local reports folder that the person running setup can't write to, such as one open only to an auditors' group with no access for Administrators, is no longer refused.
- Setup offers to give **SYSTEM** (which the scheduled task runs as) Modify access to it. No other entry changes, so administrators still get none. Unattended installs and `blackbox config set report_dir` do it without asking.
- The first report is then written by the scheduled task, not by setup.
- The status icon no longer offers to give an administrator read access to a reports folder someone chose. It says the account can't open that folder.

### SFTP inbox for Linux senders, set up by the installer

- A Linux sender can be given its collector inbox as `ACCOUNT@COLLECTOR:/PATH` (for example `bbsend@COLLECTOR:/C:/BlackboxInbox`). This is the route for FIPS mode, where SMB with a password doesn't work.
- Setup makes the sender's SSH key (ECDSA P-384, accepted in FIPS mode), shows the collector's host key fingerprint and pins it once accepted, and writes a mount unit for `/mnt/blackbox-inbox`.
- It offers to install the key on the collector, asking for the account's Windows password once. Otherwise it prints a line for the collector:
  `blackbox senders add-ssh-key ACCOUNT "restrict ecdsa-sha2-…"`
- That command adds the key, restricted to file transfer, to the file Windows OpenSSH reads for the account (an administrator's keys are in `C:\ProgramData\ssh\administrators_authorized_keys`), with the permissions OpenSSH requires. A standard user is recommended for the account.
