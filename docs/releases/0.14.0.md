## What's new

From the live re-test of 0.12.1 on 5 Oct 2026 (Windows 11 collector, Ubuntu 26.04, Server 2025).

### Original logs

- **Exported at every collection (AR2).** The original logs (`.evtx` on Windows, the audit and system logs on Linux) are now exported at every collection, while the logs still hold them, and packed into the day's archive once a day. A log that rolls over within the day (one Windows Update run can fill a 20 MB Security log in an hour) loses only what it overwrote between two collections. A log with nothing new is left out of that export.
- **What each log covers (AR2).** `archive.json` has `logs[]`: for each log, the period it actually covers (its oldest record present) and the events Blackbox knows it overwrote before they could be exported. The Original logs page shows the same, e.g. "Covers from 5 Oct 04:08; 94,565 events were overwritten before they could be exported", and `summary.json` lists it under each archive's `logs`.
- **After the clock is moved back (AR1).** If the clock was ahead and is then corrected, the next export starts at the first record written since the last one, so nothing falls between two archives. The archive and the Original logs page say so.
- **Off-box copy (AR4).** A proposal for an optional `archive_copy_to` is written up for the owner in design.md §13c. The docs now say that archives are deleted with their report under `retention_days`.

### Changing roles

- **A sender moved to another collector (L13).** Its next batch is marked as the first for the new collector, with the previous one's name, so the new collector no longer reports the earlier batches as missing. Batches also say which batches the sender still keeps, and the collector suggests `blackbox send --resend` only for those.
- **A collector or standalone computer that becomes a sender (AR3, L14).** Before its first send it makes a **final report** (its folder name ends in `_final`) of everything it had collected and received, with every original log it held, its own and other computers'. Setup says where it is. From then on it sends only its own new events: it never passes on other computers' data. A computer is shown "via" another only if its data has only ever come through that one.
- **Renamed computers (W1b).** Senders send the names they had before. The collector files events and collections under those names under the current name, and does not list an old name as another system.
- **Setup and the shutdown unit (S14, S15).** Setup run while a scheduled collection is running says so, instead of "the collector could not be reached". On Linux, a sender that stops sending removes `blackbox-shutdown.service` without leaving it "not-found failed".

### Smaller fixes

- **Interim reports (T3b)** include everything collected so far, even an event stamped just after the report (as happens right after a clock correction).
- **Last collection after a clock change (T1b)** is the latest by when it happened. A future time is marked in the report and in `status`.
- **Collector setup is not "covering of tracks" (A17b).** Blackbox's own record of setup changing its inbox, `send_to` or report folder is no longer paired with creating the delivery account.
- **Ubuntu login scripts (U4c).** AppArmor denials and file changes by the login-message programs (`who`, `landscape-sysinfo`) are part of the login scripts' row.
- **Resend (L11b).** `blackbox send --resend` exits with an error when nothing could be sent again. The collector logs a batch it already had as "already imported".
- **Firewall check (N2b).** The SMB check counts Windows 11 25H2's "File and Printer Sharing (Restrictive) (SMB-In)" rule as open, and still warns on Server 2025.
- **collect_every (C6).** `blackbox config set collect_every 15m` now changes the setting and the schedule. While events are being lost to rollover, `status`, Audit health and the tray give that command (an upgrade keeps an hourly setting).

*Correction (0.17.0, AR3b):* the final report is made only when the computer made a scheduled report since it last sent to a collector. Otherwise (for example, standalone for a few hours) there is nothing to finalise, and what it collected is sent to the collector instead; nothing is lost either way. Setup says which happened.
