## What's new

### Standalone or offline network (NET1)

- Setup asks whether a standalone computer or a collector is **on its own** or **on an offline network** with other computers (a domain or time server, file shares). Senders aren't asked.
- **On its own:** reports show network time sync as **not applicable** (still listed, with the reason) and give the update-media way to update Defender. Neither counts as a gap or appears in the fix list.
- **Offline network:** reports behave as before, expecting the network's time source and update share.
- Setting: `network = standalone | lan`; install flag: `--network`.

### Status icon for chosen groups (TRAY4)

- Setup asks which Windows groups see the status icon, for example `LAB\Auditors`. Leave it blank for all Administrators.
- Each group gets its own scheduled task (**Blackbox Status**, **Blackbox Status 2**, …). Setup checks each name is a group before going on.
- Setting: `tray_groups`; install flag: `--tray-groups`.

### Upgrades ask new questions (UPG1)

- When a version adds a setup question, **Upgrade now, keep current settings** isn't offered. **Next** goes through the pages with your settings filled in and a suggested answer for each new one.
- The console setup asks only the new questions before "Keep these settings?".
- `blackbox install --yes` uses the suggestions and lists each new setting it set.

## What's fixed

- **Linux (AlmaLinux, Rocky, RHEL): `sudo blackbox` said "command not found".** Their sudo leaves `/usr/local/bin` out of its path. Setup now also links `/usr/bin/blackbox` to the program. A file of that name that isn't a link is left alone.
- **The Linux audit-rules fix didn't work as written.** It now uses `sudo` on both sides of the pipe:
  `sudo blackbox check --audit-rules --missing | sudo install -m 0600 /dev/stdin /etc/audit/rules.d/99-blackbox.rules`, then `sudo augenrules --load`.
  Reports rewrite older senders' wording the same way.
- **Missing audit rules are grouped:** one "Missing audit rules (N)" card on Audit health and one fix-list item, with the commands once, instead of one per rule.
- **Search:** the **Common searches** menu now opens above the panels below it. Clicking a filter's name (Kind, Person, System…) now opens its list.
- **Audit health:** the column headings now say what they are ("Account management", "Removable storage"…), and the "Columns:" key under the table is gone.
- **Setup, Inbox page:** the "Accept new computers automatically" checkbox no longer covers the bottom of the **Browse…** button.
- **Setup, VirtualBox wording:** it now says that setup doesn't create the VirtualBox shared folder (you add the inbox as a Shared Folder in each VM's settings), and that a VM's files arrive as the Windows user running VirtualBox.
- **Setup, role wording:** the first page is clearer ("This computer only", "Send to a collector", "This is the collector").

## Upgrade

- **Windows:** the upgrade asks the two new questions (Network; who sees the status icon), with your other settings kept.
- **Linux:** `sudo ./install.sh` asks the Network question.
- **Silent upgrades:** `blackbox install --yes` keeps today's behaviour (`network = lan`, icon for Administrators) and says so.

## Not verified live

- The setup window (Network page, tray groups, Inbox page layout) was built and type-checked for Windows but not run; please look at it on a test PC.
- Tray tasks per group and the group check were not run on a domain.
- The `/usr/bin/blackbox` link was not run on a live AlmaLinux system.
- The report changes were checked in headless Chromium at 1280 and 1440 wide. Opening a filter list by clicking its name relies on the browser's `showPicker`, which Edge and Chrome have.
