## What's new

Fixes from the 0.16.1 re-test, and owner requests. Blackbox still only reports; it changes no system or audit settings.

### No more false High detections (AR2b, UI4b)

- **Running Blackbox by hand no longer raises High rows or "Possible covering of tracks" (AR2b).** The original logs exported at each collection are written through the Event Log service (`svchost.exe`). When Blackbox's folder is audited, each file showed as "changed or deleted Blackbox's data". The report now treats these writes as Blackbox's own when a Blackbox run on that computer covers their time and the file names match what Blackbox exports. A change or deletion there by anything else is still High.
- **The installer's helper commands are no longer rows of their own (UI4b).** The commands `Blackbox-Setup-<version>.exe` runs (its Uninstall entry, the inbox share and its permissions, the scheduled task) are listed on Blackbox's own install or upgrade row, under "Setup also ran".

### The status icon opens its windows on the first click (TRAY1)

When Windows starts a program from a task with a hidden show mode, it applies that mode to the first window the program shows. The icon's first dialog ("Make a manual report…", "Status details…") was therefore created hidden, and only the second click showed one. This was reproduced on the Windows CI runner. The icon now uses up that first show on its own hidden window, and each dialog shows itself again if it is still hidden.

### Gaps and role changes (L13b, AR3b)

- **A gap from before 0.14 now clears (L13b).** A "Missing: batches 1-280" gap noted when the collector first heard from a sender clears once that sender's batches say where its earlier batches went.
- **`blackbox gaps`** lists missing and accepted batches. **`blackbox gaps accept NAME FROM-TO "why"`** records that batches will not arrive, for example because they went to a previous collector.
  - Accepted batches are no longer counted as missing.
  - `status` lists them with who, when and why.
  - The next report has a row saying who accepted them and why; a copy also goes to the system log.
- **`blackbox status` exit code:** open gaps now make it exit 4; accepted ones don't. In 0.16.1, gaps were printed but didn't affect the exit code.
- **Becoming a sender (AR3b).** A computer that made reports becomes a sender in one of two ways:
  - If it made a scheduled report since it last sent, it makes a `_final` report first.
  - If it didn't (for example, it was standalone for a few hours), its unsent events go to the collector instead. Nothing is lost either way.
  - Setup now says which happened.

### Reports (UI13, UI14, UI15)

- **SCAP score (UI14).** The SCAP score is now in:
  - each system's Audit health view (a **SCAP score** fact), which is all a one-computer report's Audit health shows;
  - the bar at the top of Audit health ("lowest score 40% · 1 open CAT I");
  - each system's health list on the Systems page.
- **Inventory redesigned (UI15).**
  - Three tabs: **Systems**, **Drives** and **Accounts**, each with a filter box.
  - Clicking a system's row opens its drives and accounts right under it. Several can be open at once.
  - **Accounts** lists every system's accounts, with **Administrators** and **Enabled** filters.
- **Antivirus in the Audit health bar (UI13).** It counts systems whose antivirus was not checked, instead of saying "all current".
- **Deleting report folders.** The docs now explain what deleting one loses:
  - a scheduled report holds the only copy of its original logs, its hashes and its Trends counts;
  - a manual report holds nothing that isn't kept elsewhere.

### Setup (SETUP1, SETUP2)

- **Upgrade in one click.** The setup window shows your current settings, with an **Upgrade now, keep current settings** button. The console setup asks "Keep these settings and upgrade now?" first.
- **SCAP results folder.** Setup asks where this computer's SCC or OpenSCAP results are saved (`scap_results`, on a new **SCAP results** page). Type `none` to turn it off.
- **`archive_dir` on a first install.** A first install now writes the `archive_dir` chosen in setup; it used to be lost.

Release files are still unsigned: the signing secrets (A10) have not been set yet.
