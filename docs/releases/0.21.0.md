## What's new

Fixes from the 0.20.0 re-test (7 Oct 2026): original logs that could be left out of every scheduled report, log clears and the report ledger, rows shown twice, and smaller items. Blackbox still only reports; it changes no system or audit settings.

### Original logs are no longer silently left out of scheduled reports (AR7)

- Two runs in the same minute (Collect now, a hand run, setup, or a run that waited for the lock) made two exports, and the daily archive held two `.evtx` files under one name. It then failed its own check, and that computer's original logs stayed out of every later scheduled report.
- Exports are now named to the second in the archive, and never twice.
- Archives written by 0.20 with two files under one name are still read, and are repaired when they are bundled. The second file is renamed `…-2.evtx`, with its contents and hash unchanged and a note in `archive.json`.
- One archive that fails its check no longer holds back the others. The others go into the report. The bad one is moved to a `set-aside` folder next to it and is not tried again.
- When an archive is left out:
  - `blackbox status` says **ORIGINAL LOGS NOT IN REPORT <report>: …**, with the reason and where the file is, and exits 4 for 14 days;
  - the status icon notifies once;
  - the report says so on the Overview, on Original logs and in Audit health;
  - a manual report made afterwards says so too.
- "Original logs archived" is shown only when they were.

### Log clears and the report ledger (LC2b, LEDGER1b, LEDGER3, LOG1c, LOG1d)

- **Cleared logs (LC2b).** A log cleared since it last had a record exported is no longer reported as overwritten with advice to make it larger. This also covers a log that was still empty at the run that read the clear. The part it leaves out is labelled with who cleared it and when:
  - `status` has a "Log cleared:" line, with no size advice and no exit 4;
  - Original logs says "Cleared by … at …";
  - `archive.json` has `cleared` on that gap.
- **Reports recorded by 0.19 (LEDGER1b)** are checked against their manifest's file list, which the first run fills in. A file moved out of one is noticed at once. `blackbox reports` exits 4, like `status`, when it lists a report as MISSING or CHANGED.
- **Files moved out of a report (LEDGER3)** are named: "claude deleted logs-WIN11-TEST.zip from the report …". The report itself is "deleted" only when its folder went.
- **One status line per log (LOG1c).** `status` gives one "Logs incomplete" line per log, with how many times, since when, the latest part, and the same advice as its "Events lost" line.
- **Log sizes (LOG1d).** Once a collection has seen a log turn over, `check` gives the same size as `status`, from the same rate.

### Rows shown twice (UX1b, DUP2)

- Windows records each SSH sign-in as two logons at the same second. They are now one row, with sshd's address, so Logon activity counts sign-ins.
- The console host of each command in an SSH session (`conhost.exe 0xffffffff -ForceV1`, started by sshd) is counted with that person's logon instead of being a row.
- One `wevtutil cl` is one High detection. The command is folded into the log's own record of the clear, with its command line under "Cleared with".

### Smaller (UX10, CONF1b, T2b)

- The Overview's Health list says "1 of 3 systems" or "all 3 systems". It no longer shows "Logs intact" next to a log clear.
- Audit health's "Events lost to rollover" says "checked at N collections".
- `config show` gives `report_at` without a weekday unless reports are weekly.
- A Linux computer with no desktop installed (Ubuntu Server) is listed with the servers.
- At phone width, a detection card's system and time are under its text, not cut off.
- An upgrade gives `blackbox.conf` this version's comments, keeping every setting. The earlier file is kept as `blackbox.conf.old`.
- A code integrity failure (5038) on a Microsoft Defender platform file is Medium "during a Microsoft Defender update" when Defender's log shows an update to that platform version within 15 minutes. Otherwise it stays High.

Release files are still unsigned: the signing secrets (A10) have not been set yet.
