## What's new

Owner requests from 7 Oct 2026. Blackbox still only reports; it changes no system or audit settings.

### Deleted or changed reports are pointed out

A scheduled report holds the only copy of its period's original logs. Blackbox now keeps a record of each scheduled report it makes (its folder, period and the hash of its manifest). If one is later deleted, moved or changed, it is pointed out until someone records why:

- `blackbox status` says "REPORT MISSING" (or "REPORT CHANGED") and exits 4.
- The status icon notifies once.
- The next report shows "Earlier reports missing or changed" on the Overview and in Audit health's gaps.
- All reports lists it in its place as "Missing: deleted or moved".

`blackbox reports` lists the record. If a report was moved or removed on purpose, `blackbox reports accept NAME "why"` records who, when and why (a row in the next report, and a copy in the system log) and stops pointing it out. Reports removed under `retention_days` are expected and not pointed out. The record starts with the first scheduled report made by 0.19.0, so reports deleted before the upgrade are not flagged.

### All reports stays up to date

The reports index (`index.html`) is now rebuilt at every collection, not only when a report is made, so a deleted report drops off it within one collection interval.

### Keeping reports safe

An administrator on the computer can always delete files there; Blackbox does not lock its folders (its own scheduled task runs as SYSTEM, which is a member of Administrators, so a "deny delete" entry would block Blackbox too). The protection is a copy elsewhere plus the record above. reports.md now advises backing up the whole data folder after each scheduled report, to storage the computer's own administrators can't delete from.

Release files are still unsigned: the signing secrets (A10) have not been set yet.
